# ResNet / Residual Learning Cheat Sheet

각 절의 `> 허브:` 표기는 [논문 가이드](resnet_paper_guide.md)의 R 항목을 가리킵니다. 구현 API는 [쿡북](../Week%202/resnet_cookbook.md), 자기점검은 [퀴즈](resnet_questions.md), 코드는 [빈칸 노트북](../Week%202/Aing_resnet_from_scratch_blank.ipynb) 참고. 시작 전 배경은 [선수자료](resnet_prerequisites.md).

이 문서의 각 절은 `[CS§n]`이라는 좌표를 갖습니다. 본문 중 `[Cn-m]`은 [쿡북](../Week%202/resnet_cookbook.md) 절, `[N-k]`는 노트북 빈칸, `[Qn]`은 [퀴즈](resnet_questions.md) 문항을 가리킵니다 — 대괄호 한 겹이라 링크가 아니라 **좌표**입니다.

각 요소는 **비유 → 수학적 근거 → 핵심(왜 이렇게 설계했는가) → 코드 좌표** 순서로 정리했습니다. 시간이 없으면 **핵심**만 읽어도 되고, 논문 수식이 안 읽히면 **비유**부터 보시면 됩니다.

## 0) Residual Learning (핵심 아이디어)  `[CS§0]`

> 허브: [R04] [R05]
> 대응: [C3-4] · [N-16] · [Q1] [Q2] / [A1] [A2]

이 절은 ResNet 논문 전체가 걸려 있는 한 문장을 다룹니다 — **"층에게 정답 H(x)를 만들라고 시키지 말고, 입력 x와 정답의 차이 F(x) = H(x) − x만 만들라고 시키자."** 나머지 절(shortcut, block, bottleneck)은 전부 이 아이디어를 실제 텐서 연산으로 성립시키기 위한 장치입니다.

### 1. Residual Addition

- **논문 위치**: Eqn.(1) $y = F(x, \{W_i\}) + x$
- **코드 좌표**: `out = out + residual # 그대로 복사하면 운영진한테 혼나요^^`
- **비유**: 새 글을 처음부터 쓰는 게 아니라, 원본 초안을 그대로 두고 빨간펜으로 수정사항만 적는 방식입니다.
- **수학적 증명**: `+ x`가 붙는 순간 역전파가 $\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} \cdot \left(1 + \frac{\partial F}{\partial x}\right)$ 형태가 됩니다. 괄호 안의 **1**이 핵심입니다. $\frac{\partial F}{\partial x}$가 아무리 작아져도 1이 남아 있으므로, 기울기가 0으로 소멸하는 경로가 구조적으로 막힙니다. 즉 최소한 그대로 지나가는 경로가 항상 존재합니다.
- **핵심**: 기존 모델은 정답 y를 처음부터 만들어야 했지만, 잔차학습은 이미 알고 있는 입력 x를 기준으로 필요한 변화분만 학습하도록 문제를 단순화합니다. 이 덕분에 깊이가 늘어나도 "아무것도 안 하기($F=0$)"라는 쉬운 해가 항상 가능해지고, 깊어질수록 학습이 어려워지는 degradation 문제가 구조적으로 완화됩니다.
- **왜 "쉬운 해"인가 — weight가 어디서 출발하는지를 보면 보입니다**
    - **초기화는 weight를 0 근처에 둡니다.** Xavier/He 초기화 모두 평균 0, 분산이 채널 수에 반비례하는 작은 값에서 시작합니다. 순전파에서 activation의 variance가, 역전파에서 gradient의 variance가 층을 지나며 폭발하거나 소멸하지 않게 맞춘 값입니다. weight decay(L2)도 학습 내내 weight를 0 쪽으로 끌어당깁니다 — 이쪽은 variance 안정이 아니라 정규화(모델이 특정 입력에 과하게 반응하지 않게 하는 것)가 목적이지만, **미는 방향은 같습니다.** 결과적으로 conv filter는 학습 시작 시점에 **zero matrix에 가깝고, 특별한 이유가 없으면 계속 그 근처에 머무릅니다.**
    - **그런데 깊은 네트워크가 원하는 해는 "입력을 거의 안 바꾸는 것"입니다.** 층을 통과할 때마다 x가 크게 뒤틀리면 깊이가 늘수록 표현이 망가집니다. 즉 이상적으로는 출력 ≈ 입력이어야 합니다.
    - **skip connection이 없으면**: 층이 직접 $F(x) \approx x$를 만들어야 합니다. 그러려면 conv filter가 **identity kernel** — 커널 중심 탭만 1이고 나머지는 전부 0, 채널 대응도 일대일인 아주 특수한 모양 — 로 학습되어야 합니다. 이건 초기값(0 근처)에서도 멀고, weight decay가 당기는 방향과도 정반대입니다. **가고 싶은 곳이 출발점 반대편에 있는 셈입니다.**
    - **skip connection이 있으면**: 출력이 $x + F(x)$이므로 출력 ≈ 입력이 되려면 $F(x) \approx 0$이면 됩니다. filter가 **원래 있던 0 근처에 그냥 머무르면** 끝입니다. 더 학습할 것이 없습니다.
    - **그래서**: 같은 목표(입력 보존)를 두고 skip connection이 없을 때는 특수한 identity kernel까지 이동해야 하고, 있을 때는 출발점에 가만히 있으면 됩니다. Residual addition이 학습을 쉽게 만든다는 말의 실체가 이것입니다. 논문의 "identity mapping이 optimal에 가깝다면 solver가 zero로 밀어붙이기가 더 쉽다"는 문장(§3.1)과 같은 얘기입니다.
    - **덧붙임**: 여기서 말한 "0 근처"는 residual branch **마지막 BN의 $\gamma$로도 직접 조작할 수 있습니다. 그 $\gamma$를 0으로 초기화하면 학습 시작 시 $F(x)=0$, 즉 블록이 **정확히** identity에서 출발합니다. 이 논문 밖의 기법(zero-init residual)이지만, 위 논리가 맞다는 실증에 가깝습니다.
- **주의 — degradation은 overfitting이 아닙니다**: 논문 Figure 1에서 56층 plain net은 20층보다 **training error**부터 높습니다. 과적합이면 training error는 낮고 test error만 높아야 하므로, 이것은 표현력 부족도 과적합도 아닌 **최적화의 문제**입니다. Residual learning은 모델 용량을 늘리는 기법이 아니라 최적화를 쉽게 만드는 기법입니다. → [퀴즈](resnet_questions.md) [Q1]

### 2. Residual Function

- **논문 위치**: Figure 2
- **코드 좌표**: `conv → bn → relu → conv → bn`
- **비유**: 집을 새로 짓는 게 아니라, 이미 튼튼한 집(입력 x)에 생긴 흠집만 메우는 보수공사입니다.
- **수학적 근거**: 잔차는 사실상 $F(x) \approx y - x$를 학습하는 셈이라, 목표가 전체 y가 아니라 차이(변화분)로 바뀝니다. 특히 최적해가 '거의 그대로'라면 정답은 $F(x)=0$ 근처로 몰려 학습이 쉬워집니다(왜 그것이 쉬운지는 위 §0-1의 "왜 쉬운 해인가" 참고).
- **핵심**: 기존 모델은 매 층마다 입력을 새롭게 변환해 정답에 가까워져야 했기 때문에, 깊어질수록 불필요한 변화가 누적되기 쉬웠습니다. 잔차 함수는 입력 x를 기준으로 정말로 필요한 변화분만 학습하도록 문제를 바꿔, 아무 변화가 필요 없을 경우에는 그대로 두는 것($F(x)=0$)이 가장 쉬운 선택이 되게 만듭니다. 이 덕분에 네트워크는 깊어져도 입력을 망가뜨리며 헤매지 않고, 학습이 자연스럽게 "유지 + 필요한 만큼만 수정"하는 방향으로 정렬됩니다.
- **왜 마지막이 BN인가**: residual branch는 `conv → bn → relu → conv → bn`으로 끝나고, 마지막 ReLU는 덧셈 **뒤**에 있습니다. branch 끝에 ReLU를 두면 $F(x) \ge 0$이 되어 잔차가 뺄셈(음의 보정)을 표현할 수 없게 됩니다. → §2 Post-activation

## 1) Shortcut 연결 방식 (Option A / B)  `[CS§1]`

> 허브: [R05] [R08]
> 대응: [C1] [C2] [C3-5] · [N-1]~[N-9] · [Q3] / [A3]

$F(x) + x$를 하려면 두 텐서의 **shape가 같아야** 합니다. 그런데 stage가 바뀌면 채널이 늘고 해상도가 절반이 되므로 그대로는 못 더합니다. 이 절의 세 방식은 전부 "그 차원을 어떻게 맞출 것인가"에 대한 서로 다른 답입니다.

| | 파라미터 추가 | 언제 쓰나 |
| --- | --- | --- |
| Identity | 없음 | 차원이 그대로일 때 (대부분의 블록) |
| Zero-padding (Option A) | 없음 | 차원이 바뀔 때, 통제된 실험용 (CIFAR-10) |
| Projection (Option B) | 1×1 conv | 차원이 바뀔 때, 성능 우선 (ImageNet) |

논문은 Option C(**모든** shortcut을 projection으로)도 실험했지만, A/B/C의 성능 차이가 작아 "projection이 degradation 해결의 본질이 아니다"라는 근거로 삼고 C는 채택하지 않았습니다. → [퀴즈](resnet_questions.md) [Q3]

### 1. Identity Shortcut

- **논문 위치**: Option A, Eqn.(1) $y = F(x, \{W_i\}) + x$
- **코드 좌표**: `nn.Identity()`
- **비유**: 복잡한 골목길(residual branch) 옆에 직진 고속도로 하나를 공짜로 깔아둔 것입니다.
- **수학적 근거**: shortcut이 그대로 x라서, 이 경로의 도함수는 항상 $I$(항등)입니다. 학습 신호가 '변환을 거치지 않고' 지나갈 수 있습니다.
- **핵심**: 기존의 깊은 네트워크에서는 학습 신호가 여러 변환을 거치며 약해지거나 왜곡되기 쉬웠습니다. Identity shortcut은 입력 x를 아무 변화 없이 그대로 전달하는 경로를 추가해, 모델이 어떤 층에서도 "굳이 변환하지 않아도 된다"는 선택지를 항상 갖게 합니다. 이 경로는 파라미터를 전혀 늘리지 않으면서도, 깊어질수록 학습이 막히는 문제를 구조적으로 완화해 모델의 성능이 아니라 **학습 가능성 자체**를 안정화하는 역할을 합니다.
- **적용 조건**: 입력과 출력의 차원이 같을 때 쓰는 기본 shortcut입니다. 한 stage 안의 블록은 대부분 여기에 해당합니다.
- **구현 메모**: 통과일 때 `None`을 넣으면 `forward`에서 매번 `if`를 써야 하므로, "아무것도 안 하는 모듈"인 `nn.Identity()`를 넣어 분기를 `__init__` 쪽으로 몰아넣습니다. → [쿡북](../Week%202/resnet_cookbook.md) [C0]

### 2. Projection Shortcut

- **논문 위치**: Option B, Eqn.(2) $y = F(x, \{W_i\}) + W_s x$
- **코드 좌표**: `ShortcutProjection`
- **비유**: 플러그 모양이 달라서 안 꽂히면, 어댑터(변환 젠더)로 규격을 맞추는 것입니다.
- **수학적 근거**: $W_s$(보통 1×1 conv, stride=2)가 채널과 해상도를 동시에 바꿔 덧셈이 가능한 동일 차원으로 보냅니다. 'add 가능 조건'을 만족시키는 수학적 장치입니다.
- **핵심**: 스테이지가 바뀌는 지점에서는 해상도나 채널 수가 달라져 입력 x를 그대로 더할 수 없는 문제가 생깁니다. Projection shortcut은 이 불일치를 단순히 피하는 대신, 1×1 conv를 통해 **어떤 정보를 남기고 어떤 정보를 줄일지를 학습**하면서 입력을 다음 스테이지와 호환되는 형태로 변환합니다. 그 결과, 구조적 제약(add 가능 조건)을 만족시키는 동시에 다운샘플링 구간에서도 중요한 정보가 끊기지 않고 전달되도록 합니다.
- **적용 조건**: 차원이 바뀌는 구간에서 성능과 안정성을 우선할 때 선택합니다. ImageNet ResNet의 기본값입니다.
- **비용**: 1×1 conv 하나가 추가되므로 파라미터와 연산이 늘어납니다. 다만 stage 경계에서만 쓰이므로 전체 대비 비중은 작습니다.
- **주의**: shortcut의 1×1 conv에도 BN이 붙습니다. 그리고 이 conv에는 `bias=False`입니다 — 뒤에 BN이 평균을 빼기 때문에 bias가 무의미해집니다. → [쿡북](../Week%202/resnet_cookbook.md) [C3-2]

### 3. Zero-padding Shortcut

- **논문 위치**: Option A 응용 (Figure 4 right)
- **코드 좌표**: `ShortcutZeroPad`
- **비유**: 단체 사진에서 인원이 모자라면, 빈 의자(0)를 옆에 두어 줄을 맞추는 것입니다.
- **수학적 근거**: 채널을 $[x, 0]$처럼 0으로 패딩해 차원만 맞춘 뒤 $F(x)+x$를 수행합니다. $W_s$를 학습하지 않는 고정 매핑이라 파라미터가 늘지 않습니다.
- **핵심**: CIFAR-10 설정에서는 채널 수가 바뀌는 구간에서도 **추가 파라미터 없이** residual 구조를 유지할 필요가 있었습니다. Zero-padding shortcut은 학습 가능한 변환을 아예 도입하지 않고, 입력에 0을 덧붙여 차원만 맞춘 채 그대로 더하는 방식을 선택합니다. 이 설계는 성능을 최대화하기 위한 선택이 아니라, **잔차 연결 자체가 학습을 쉽게 만든다는 효과를 추가 파라미터의 도움 없이도 확인하기 위한 실험적 통제 장치**입니다.
- **두 단계로 나뉩니다**: 해상도는 slicing(`x[:, :, ::2, ::2]`)으로 절반으로 줄이고, 채널은 부족한 만큼 0 텐서를 만들어 `torch.cat`으로 이어 붙입니다. 순서를 바꿔도 결과는 같지만 노트북은 slicing → padding 순서입니다. → [쿡북](../Week%202/resnet_cookbook.md) [C1-1] `[C1-2]`
- **왜 성능이 아니라 통제인가**: 이 설정에서 성능이 좋아졌다면 그 원인이 "파라미터가 늘어서"일 수는 없습니다. 원인을 잔차 구조 하나로 좁히기 위한 실험 설계입니다.

## 2) Basic Residual Block  `[CS§2]`

> 허브: [R07] [R06]
> 대응: [C3] · [N-10]~[N-17] · [Q2] / [A2]

Residual learning을 실제 층으로 구현한 최소 단위입니다. ResNet-18/34가 이 블록으로만 이루어져 있습니다.

### 1. Basic Block

- **논문 위치**: Figure 5 (left)
- **코드 좌표**: `BasicBlockV1`
- **비유**: 한 번에 인테리어를 갈아엎지 말고, 사포질 → 한 번 더 사포질처럼 작은 개선을 두 번 누적하는 방식입니다.
- **수학적 근거**: $F(x)$를 3×3 conv 두 번으로 구성해 '작은 변화'를 만들고, 마지막에 `+x`로 합칩니다. 깊게 쌓아도 각 블록은 '미세 업데이트'로 동작해 최적화가 안정적입니다.
- **핵심**: 기존의 깊은 네트워크에서는 여러 층이 한꺼번에 큰 변화를 만들려다 학습이 불안정해지기 쉬웠습니다. Basic Residual Block은 한 블록 안에서 3×3 conv 두 개로 아주 작은 변화만 만들고, 이를 입력과 더해 누적하도록 설계됩니다. 그 결과 각 블록은 "크게 바꾸는 단계"가 아니라 **조금씩 고쳐 나가는 반복 개선 단계**로 동작하며, 네트워크가 깊어져도 학습이 무너지지 않는 구조가 됩니다.
- **정확한 연산 순서**: `conv3×3 → BN → ReLU → conv3×3 → BN → (+ shortcut) → ReLU`. 마지막 ReLU가 덧셈 **뒤**에 있다는 점이 v1의 정의입니다.
- **(풀어 쓰기) 왜 하필 conv가 두 개인가 — 1개도 3개도 아닌 이유**
    - **1개면 안 되는 이유 — 잔차가 선형이 됩니다.** conv 하나짜리 블록은 `conv → BN`뿐이라 그 사이에 ReLU가 낄 자리가 없습니다. BN도 (학습 후 고정되면) affine 변환이므로 $F(x)$ 전체가 **선형 변환 하나**가 됩니다. 그러면 $y = x + Wx = (I+W)x$가 되어 블록을 아무리 쌓아도 결국 행렬 곱 하나로 접히고, **깊이가 표현력을 늘리지 못합니다.** 비선형성이 있어야 층을 쌓는 의미가 생깁니다.
    - **2개면 되는 이유 — 비선형성 1개가 들어가는 최소 구성.** `conv → BN → ReLU → conv → BN`에서 가운데 ReLU 하나가 $F$를 비선형 함수로 만듭니다. 동시에 3×3을 두 번 쌓으면 **receptive field가 5×5**가 되어, 5×5 conv 하나(25 파라미터)보다 적은 비용(3×3 두 개 = 18 파라미터)으로 같은 시야를 얻습니다. VGG가 먼저 쓴 논리를 residual block 안으로 가져온 것입니다.
    - **3개 이상이 아닌 이유 — 블록이 두꺼워지면 residual의 이점이 흐려집니다.** 잔차 하나가 담당하는 변화가 커질수록 "미세 업데이트"라는 성격이 사라지고, shortcut 사이의 거리가 멀어져 gradient가 그대로 지나가는 구간이 줄어듭니다. 논문도 §3.3에서 층 2~3개짜리 블록을 언급하며, **1층짜리 블록은 이점을 관찰하지 못했다**고 적습니다(위의 선형 문제와 같은 이야기입니다).
    - 참고로 bottleneck의 conv 3개는 여기서 말하는 "더 깊은 잔차"가 아닙니다. 1×1 두 개는 채널을 줄였다 늘리는 **비용 장치**이고, 실제로 공간 패턴을 보는 건 가운데 3×3 하나뿐입니다. → §3
- **`expansion = 1`**: Basic block은 입력 채널과 출력 채널이 같습니다. 이 값이 bottleneck과 갈리는 지점입니다. → §3

### 2. Post-activation

- **논문 위치**: Figure 2 (v2 언급은 **이 논문 밖** — 아래 출처 주의 참고)
- **코드 좌표**: `relu(out)` (add 이후)
- **비유**: 원본과 수정본을 합친 뒤, 최종 도장(활성화)을 찍어 '이 값은 통과/보류'를 결정하는 것입니다.
- **수학적 근거**: v1은 $y = \mathrm{ReLU}(F(x)+x)$입니다. 즉 비선형성이 **합산 결과 전체**에 적용됩니다.
- **핵심**: Residual 구조에서는 학습 신호가 더하기를 통해 잘 흐르더라도, 그 이후에 어떤 연산을 두느냐에 따라 흐름이 다시 막힐 수 있습니다. ResNet v1은 잔차를 더한 뒤에 ReLU를 적용해 표현력을 높이는 선택을 했지만, 이로 인해 경우에 따라 shortcut을 통해 전달된 신호까지 함께 차단될 가능성이 생깁니다. 이 한계를 인식하고, 이후 ResNet v2에서는 비선형성을 더하기 **이전**으로 옮겨 잔차 경로와 identity 경로의 흐름을 더 부드럽게 유지하도록 구조를 개선했습니다.
- **어디서 신호가 막히는가**: ReLU는 음수 입력에 대해 도함수가 0입니다. 덧셈 결과가 음수인 위치에서는 shortcut을 타고 온 성분까지 함께 0으로 곱해지므로, "항상 열려 있는 고속도로"가 그 위치에서는 닫힙니다. v2의 pre-activation은 identity 경로에 아무 연산도 두지 않아 이 문제를 없앱니다.
- **출처 주의**: v2(pre-activation) 이야기는 **이 논문(arXiv:1512.03385)에 없습니다.** 후속 논문 He et al. 2016, *Identity Mappings in Deep Residual Networks*의 내용입니다. Figure 2는 v1의 post-activation만 보여줍니다 → [R06]. 스터디 코드도 v1 기준이므로, 구현할 때 v2 순서를 섞지 않도록 주의해 주세요.

## 3) Bottleneck Block (깊은 ResNet)  `[CS§3]`

> 허브: [R12]
> 대응: [C4] · [N-23] [N-25] · [Q4] / [A4]

ResNet-50 이상에서 basic block을 대체하는 블록입니다. 목적은 표현력 향상이 아니라 **같은 예산으로 더 깊게 쌓기**입니다.

### 1. Bottleneck Block

- **논문 위치**: Figure 5 (right)
- **코드 좌표**: `BottleneckV1`
- **비유**: 큰 짐을 압축(좁은 통로 통과) → 이동 → 재포장해서 운송비를 줄이는 택배입니다.
- **수학적 근거**: 1×1로 채널을 줄인 뒤(압축), 3×3을 작아진 채널에서만 돌리고, 다시 1×1로 확장합니다. 3×3 conv의 연산량은 (입력 채널 × 출력 채널 × 9 × H × W)로 **채널 수의 곱에 비례**하므로, 양쪽 채널을 1/4로 줄이면 그 구간 비용이 대략 1/16이 됩니다. 3×3 연산이 가장 비싸니, 그 구간을 얇게 만드는 게 포인트입니다.
- **핵심**: ResNet을 더 깊게 쌓으려 할수록 문제는 표현력이 아니라 **연산량과 최적화 비용이 급격히 커진다**는 점이었습니다. Bottleneck 구조는 깊이를 줄이지 않으면서도 가장 비용이 큰 3×3 연산을 채널이 줄어든 상태에서만 수행하도록 설계해, 계산 부담을 구조적으로 억제합니다. 그 결과 "깊이는 유지하되 비싼 연산은 최소화"하는 방식으로 아주 깊은 ResNet을 실제로 학습 가능한 모델로 만듭니다.
- **연산 순서**: `1×1(축소) → BN → ReLU → 3×3 → BN → ReLU → 1×1(확장) → BN → (+ shortcut) → ReLU`. conv가 세 개이므로 ResNet-50의 층 수 계산도 블록당 3으로 셉니다.
- **(풀어 쓰기) 실제 숫자로 — 왜 굳이 압축했다 푸는가**
    - 3×3 conv 한 개의 파라미터 수는 $C_{in} \times C_{out} \times 3 \times 3$입니다. **입출력 채널의 곱**에 비례한다는 게 요점입니다 — 한쪽만 줄여도 절반, 양쪽 다 줄이면 제곱으로 줄어듭니다.
    - **basic block으로 256채널을 처리한다면**: 3×3 conv 두 개가 전부 256 → 256이므로 $256 \times 256 \times 9 \times 2 \approx$ **118만 개**입니다.
    - **bottleneck으로 같은 256채널을 처리하면**: 1×1 축소(256 → 64) $= 256 \times 64 = 1.6만$, 3×3(64 → 64) $= 64 \times 64 \times 9 \approx 3.7만$, 1×1 확장(64 → 256) $= 1.6만$. 합쳐서 **약 7만 개**입니다.
    - **즉 같은 입출력 폭에서 약 1/17입니다.** 가장 비싼 3×3을 1/16로 줄이는 대신 싼 1×1 두 개를 추가로 낸 결과이고, 이 절감분을 **블록 개수(깊이)로 바꿔 쓴 것**이 ResNet-50/101/152입니다. 논문이 ResNet-50과 ResNet-34의 FLOPs가 비슷하다고 적는 근거가 이 계산입니다.
    - **핵심은 "표현력을 포기했다"가 아닙니다.** 입출력은 여전히 256채널로 두껍고, 얇아지는 건 가운데 한 구간뿐입니다. 넓은 입구·좁은 허리·넓은 출구라서 이름이 bottleneck입니다.
- **stride를 어디에 두는가**: 이 논문(v1)은 3×3 conv에 stride를 둡니다. 후대 구현(torchvision의 ResNet-B 등)은 첫 1×1로 옮기기도 하는데, 이건 논문 밖의 개선입니다.

### 2. Channel Expansion

- **논문 위치**: Table 1
- **코드 좌표**: `expansion = 4`
- **비유**: 압축해서 옮긴 뒤, 목적지에서 더 큰 서랍(4배 채널)에 정리해 활용도를 높이는 것입니다.
- **수학적 근거**: `expansion = 4`는 bottleneck 출력 채널이 내부 채널의 4배가 된다는 뜻입니다. 예를 들어 내부 64채널이면 출력은 256채널입니다. shortcut과 더하려면 입력도 256이어야 하므로, 차원을 맞추기 위해 종종 projection이 필요합니다.
- **핵심**: Bottleneck 구조에서는 연산 비용을 줄이기 위해 중간 단계에서 의도적으로 채널 수를 크게 줄입니다. 하지만 이 상태로는 표현력이 부족해질 수 있기 때문에, 마지막 단계에서 채널을 다시 확장해 다음 블록에서 사용할 충분한 표현 공간을 복원합니다. 이로써 중간 단계는 **계산 효율**, 마지막 단계는 **표현력 확보**라는 역할로 분리되고, 전체 구조는 "저차원에서 계산하고 고차원으로 복원하는" 깊은 네트워크에 최적화된 효율 설계가 됩니다.
- **왜 identity shortcut이 특히 중요해지는가**: 출력이 4배로 두꺼우므로, 만약 shortcut까지 매번 projection이라면 그 1×1 conv가 고차원 ↔ 고차원 변환이 되어 비용이 급증합니다. 채널이 유지되는 대부분의 블록에서 shortcut을 identity로 두는 것이 bottleneck 설계가 성립하는 전제입니다. → [퀴즈](resnet_questions.md) [Q4]
- **구현 주의**: 코드에서 채널 수를 계산할 때 `planes`(내부 채널)와 `planes * expansion`(출력 채널)을 헷갈리면 shape 에러가 납니다. shortcut 쪽 목표 채널은 항상 `planes * expansion`입니다. → [쿡북](../Week%202/resnet_cookbook.md) [C4]

## 4) Stage 구조와 Downsampling  `[CS§4]`

> 허브: [R16]
> 대응: [C5-2] [C5-4] · [N-18]~[N-21] [N-24] [N-26] [N-27] · [Q5] / [A5]

블록을 어떻게 배열할 것인가에 대한 규칙입니다. 개별 블록이 아니라 **네트워크 전체의 뼈대**를 정합니다.

### 1. Stage-based Design

- **논문 위치**: Figure 3 / Table 1
- **코드 좌표**: `layer1 ~ layer4`
- **비유**: 책을 챕터로 나눠, 한 챕터에서는 같은 글자 크기(해상도)로 읽다가 챕터가 바뀔 때만 레이아웃을 바꾸는 것입니다.
- **수학적 근거**: stage 내부에서는 (H, W, 채널)이 일정하고, stage 경계에서만 stride와 채널이 바뀝니다. 해상도가 절반이 될 때 채널이 2배가 되므로 층당 연산량이 대략 보존됩니다. 이는 네트워크가 스케일별 특징을 안정적으로 학습하게 합니다.
- **핵심**: 네트워크가 깊어질수록 한 층에서 처리해야 할 정보의 성격은 점점 국소적인 디테일에서 추상적인 의미로 바뀝니다. Stage 구조는 해상도와 채널 수를 일정 구간마다만 바꾸도록 제한해, 각 구간이 하나의 스케일에 집중해서 특징을 학습하도록 설계된 구조입니다. 이로써 얕은 stage는 세밀한 공간 패턴을, 깊은 stage는 보다 추상적인 의미를 담당하게 되며, 멀티스케일 표현을 자연스럽게 쌓아 올리는 커리큘럼이 형성됩니다.
- **ImageNet 기준 흐름**: 224 → (stem 7×7 s2) 112 → (maxpool) 56 → layer1 56 → layer2 28 → layer3 14 → layer4 7. 채널은 64 → 128 → 256 → 512로 두 배씩 늘어납니다.
- **(풀어 쓰기) "해상도 절반 ↔ 채널 2배"는 왜 짝을 이루는가**
    - conv 한 층의 연산량은 대략 $C_{in} \times C_{out} \times k^2 \times H \times W$입니다. 여기서 **해상도는 1제곱, 채널은 2제곱으로** 들어간다는 비대칭이 핵심입니다.
    - 해상도를 절반으로 줄이면 $H \times W$가 **1/4**이 됩니다. 이때 채널을 2배로 하면 $C_{in} \times C_{out}$이 **4배**가 되어 정확히 상쇄됩니다. 그래서 stage가 넘어가도 **층 하나당 연산량이 대략 일정하게 유지**됩니다.
    - 이 설계 덕분에 "어느 stage에 블록을 더 넣을까"를 고민할 때 **연산 예산을 층 수로 바로 환산할 수 있습니다.** ResNet-34의 (3, 4, 6, 3)처럼 stage별 블록 수를 자유롭게 조정해도 총비용이 예측 가능해지는 이유입니다.
    - **채널을 2배로 늘리는 쪽의 이유는 따로 있습니다.** 해상도가 줄면 한 위치가 담아야 할 정보량이 늘어나는데(더 넓은 영역을 요약하므로), 채널이 그대로면 그 정보가 압축 손실로 사라집니다. 채널 증가는 그 손실을 보상하는 쪽이고, 연산량 보존은 거기서 따라 나오는 결과에 가깝습니다.
- **왜 stage 안에서는 해상도를 안 바꾸는가**: 같은 stage의 블록들이 전부 같은 shape이면 shortcut이 전부 identity가 되어, 파라미터를 늘리지 않고 블록을 얼마든지 더 쌓을 수 있습니다. 깊이만 바꿔 가며 비교하는 실험이 가능해지는 이유이기도 합니다.

### 2. Downsampling at Stage Start

- **논문 위치**: Table 1
- **코드 좌표**: `stride=2` (각 stage의 첫 block에만)
- **비유**: 지도에서 아무 데서나 줌 아웃하면 길을 잃으니, 챕터 시작점에서만 딱 한 번 줌 아웃하는 것입니다.
- **수학적 근거**: 첫 블록의 stride=2가 공간 해상도를 절반으로 줄이고(요약), 동시에 채널을 늘립니다(표현력 확보). 더하기를 유지하려면 shortcut도 같은 차원으로 맞춰야 하므로, 이 블록에서만 projection 또는 zero-padding이 등장합니다.
- **핵심**: 해상도를 줄이는 다운샘플링은 불가피하지만, 잘못 쓰면 중요한 공간 정보를 한꺼번에 잃을 위험이 있습니다. ResNet은 이 위험을 네트워크 전체에 흩뿌리지 않고, **스테이지가 시작되는 지점에만** 다운샘플링을 집중시켜 정보 손실이 일어나는 위치를 명확하게 관리합니다. 또한 이 구간에서도 residual 경로를 유지해, 요약 과정에서 생기는 충격을 완화하고 다음 스테이지로의 정보 흐름을 안정적으로 이어가도록 설계했습니다.
- **구현에서 가장 자주 틀리는 지점**: stride와 채널 증가가 **같은 블록에서 동시에** 일어난다는 점입니다. 코드에서 `stride != 1 or in_planes != planes * expansion` 조건 하나로 shortcut 분기를 판단하는 이유가 여기 있습니다 — 둘 중 하나만 달라도 identity로는 더할 수 없습니다. → [쿡북](../Week%202/resnet_cookbook.md) [C5]
- **layer1은 예외**: ImageNet에서는 stem의 maxpool이 이미 해상도를 줄여 놓았으므로 layer1의 stride는 1입니다. CIFAR-10에서는 stem에 pooling이 없어 첫 stage 역시 stride 1입니다.

## 5) CIFAR-10 코드에서 다르게 구현한 부분  `[CS§5]`

> 허브: [R15]
> 대응: [C5-1] [C6] · [N-28]~[N-30] · [Q5] / [A5]

논문 §4.2의 CIFAR-10 실험은 ImageNet 모델의 축소판이 아닙니다. **목적이 다릅니다** — ImageNet 실험이 "성능이 좋은가"를 묻는다면, CIFAR-10 실험은 "깊이가 늘어도 학습이 되는가"만을 통제된 조건에서 묻습니다. 아래 세 가지 차이는 전부 그 통제에서 나옵니다.

### 1. 6n+2 Depth Rule

- **논문 위치**: §4.2 CIFAR-10 and Analysis
- **코드 좌표**: `depth = 6n + 2`
- **비유**: 레고가 '구역당 n세트'로 고정이라, n만 바꾸면 전체 높이가 정확히 예측되는 설명서입니다.
- **수학적 근거**: (블록당 conv 2개) × (3 stage × n블록) = **6n**, 여기에 stem conv 1개 + 마지막 분류층(FC) 1개를 더해 **6n+2**가 됩니다. n=3이면 20층, n=5면 32층, n=9면 56층, n=18이면 110층입니다.
- **핵심**: 깊이를 늘린다는 것은 여러 요소를 동시에 바꾸기 쉬운 작업입니다. 그래서 CIFAR-10 실험에서는 깊이 외의 조건을 모두 고정한 채, 블록 개수 n 하나만 조절해 네트워크를 확장하도록 설계했습니다. 이 규칙은 모델을 편하게 만들기 위한 장치가 아니라, **깊이 증가 그 자체가 학습과 성능에 어떤 영향을 미치는지를 혼선 없이 관찰하기 위한 실험적 통제 구조**입니다.
- **stage가 3개인 이유**: 입력이 32×32라 32 → 16 → 8까지가 한계입니다. ImageNet의 4 stage를 그대로 쓸 수 없습니다. 채널도 16 → 32 → 64로 ImageNet(64 → 512)보다 훨씬 얇습니다.
- **(풀어 쓰기) 6n+2의 6과 2가 각각 어디서 오는가**
    - **6 = 2 × 3입니다.** 2는 basic block 하나에 든 conv 개수, 3은 stage 개수입니다. 각 stage에 블록을 n개씩 넣으므로 $2 \times 3 \times n = 6n$.
    - **2는 블록 밖의 두 층입니다.** 앞의 stem conv(3×3) 하나와 맨 끝 FC 하나. 이 둘은 n과 무관하게 **항상 정확히 1개씩**이라 상수항이 됩니다.
    - 그래서 n을 바꿔도 바뀌는 건 오직 "각 stage의 블록 개수"뿐입니다 — stage 수도, stem도, 분류기도, 채널 폭(16/32/64)도 전부 고정입니다. **깊이 하나만 변수로 남기려고** 이렇게 짠 것입니다.
    - **왜 6의 배수 + 2만 가능한가**: 세 stage에 블록을 **똑같이** n개씩 넣는다는 제약 때문입니다. 그래서 20, 32, 44, 56, 110은 되지만 그 사이 값(예: 25층)은 이 규칙으로 만들 수 없습니다. 반대로 말하면 **"20층과 56층은 깊이 말고 다른 게 없다"**는 것이 보장되고, Figure 6의 비교가 성립합니다.
    - **역산 연습**: 110층이면 $110 = 6n + 2 \Rightarrow n = 18$. stage당 블록 18개, 총 블록 54개입니다.
- **세는 법 확인**: shortcut의 1×1 conv와 BN, pooling은 깊이에 세지 않습니다. weight를 가진 **주 경로의 층**만 셉니다. → [퀴즈](resnet_questions.md) [Q5]

### 2. Identity Shortcut Only

- **논문 위치**: §4.2 CIFAR-10 and Analysis
- **코드 좌표**: `shortcut="zero_pad"`
- **비유**: 비교 실험인데 누군가만 어댑터(추가 부품)를 쓰면 반칙이니, 추가 부품 없이 규격만 맞추는 것입니다.
- **수학적 근거**: projection(학습되는 $W_s$)을 쓰지 않고, 필요한 경우에만 zero-pad(고정 매핑)로 차원을 맞춰 $F(x)+x$를 유지합니다. 따라서 n을 키워도 늘어나는 파라미터는 residual branch의 conv뿐입니다.
- **핵심**: CIFAR-10 실험의 목표는 성능을 최대한 끌어올리는 것이 아니라, **잔차 연결 구조 자체가 학습을 쉽게 만드는지** 확인하는 데 있었습니다. 이를 위해 projection처럼 추가 학습 파라미터가 들어가는 shortcut을 배제하고, 필요한 경우에만 zero-padding으로 차원만 맞춘 채 residual 구조를 유지했습니다. 이 설정에서 성능이 향상된다면, 그 원인은 모델 용량 증가가 아니라 **잔차 경로가 만들어낸 최적화 구조 자체의 효과**라고 보다 강하게 결론지을 수 있습니다.
- **읽는 법**: "Option A가 Option B보다 좋아서 골랐다"가 아닙니다. 논문 자체가 ImageNet에서는 B가 조금 낫다고 보고합니다. 여기서 A를 쓴 건 **성능 선택이 아니라 실험 설계**입니다.

### 3. Small Stem

- **논문 위치**: §4.2 CIFAR-10 and Analysis
- **코드 좌표**: `3×3 conv` (stride 1, maxpool 없음)
- **비유**: 32×32 미니 사진을 7×7 큰 도장으로 찍으면 디테일이 뭉개지니, 작은 도장(3×3)으로 조심히 시작하는 것입니다.
- **수학적 근거**: ImageNet stem은 `7×7 conv (stride 2) → maxpool (stride 2)`로 입력을 1/4로 줄입니다. 32×32에 그대로 적용하면 첫 stage 입력이 8×8이 되어 남은 깊이가 쓸 공간이 없습니다. CIFAR stem은 3×3 stride 1에 pooling도 없어 32×32를 그대로 유지합니다.
- **핵심**: 기존 모델에서 아무리 잔차학습으로 깊이를 확보해도, 초반 단계에서 공간적 디테일이 한 번에 사라지면 이후의 깊이는 그 정보를 되살릴 수 없습니다. 그래서 ResNet에서는 깊게 쌓는 혁신을 살리기 위해, 입력단부터 세밀한 정보를 최대한 보존하도록 입구(stem)를 더 섬세하게 설계합니다.
- **일반 원칙**: stem의 다운샘플링 강도는 입력 해상도에 맞춰야 합니다. 입력이 작으면 stem도 작아야 한다는 규칙은 CIFAR에만 해당하는 요령이 아니라 다른 소해상도 데이터셋에도 그대로 적용됩니다.

## 6) Global Average Pooling  `[CS§6]`

> 허브: [R17]
> 대응: [C5-3] · [N-22] · [A5]

마지막 stage의 feature map을 분류기로 넘기는 방법입니다. AlexNet/VGG가 쓰던 거대한 FC 층을 대체합니다.

### 1. Global Avg Pool

- **논문 위치**: Table 1 (마지막 행 `average pool, 1000-d fc, softmax`)
- **코드 좌표**: `nn.AdaptiveAvgPool2d((1, 1))`
- **비유**: 각 채널을 '특정 패턴을 감지하는 센서'라고 보면, Global Average Pooling은 그 센서가 이미지 전체에서 얼마나 자주, 강하게 반응했는지의 **평균 점수만** 남기는 방식입니다.
- **수학적 근거**: 각 채널의 feature map(H×W)을 전부 평균내어 채널당 하나의 값으로 만듭니다. `[N, C, H, W]` → `[N, C, 1, 1]` → (flatten) → `[N, C]`. 이렇게 하면 큰 FC 층 없이도 분류가 가능하고 파라미터 수가 크게 줄어듭니다.
- **핵심**: 합성곱 층이 깊어질수록 특징의 **위치** 정보는 점점 덜 중요해지고, 그 특징이 **존재하는지 여부** 자체가 더 중요해집니다. Global Average Pooling은 각 채널의 반응을 공간 전체에서 평균내어, 특정 패턴이 어디에 나타났는지가 아니라 얼마나 일관되게 나타났는지를 기준으로 판단하도록 만듭니다. 이 과정은 파라미터를 줄이기 위한 단순한 압축이 아니라, 모델이 위치에 집착하지 않고 **의미 자체에 집중하도록 유도하는 구조적 규제(regularization)** 역할을 합니다.
- **(풀어 쓰기) 파라미터 절감 규모를 숫자로**
    - **VGG-16 방식**: 마지막 feature map이 `[512, 7, 7]`입니다. 이걸 통째로 flatten하면 $512 \times 7 \times 7 = 25{,}088$차원 벡터가 되고, 여기에 4096짜리 FC를 붙이면 $25{,}088 \times 4096 \approx$ **1억 개**입니다. FC 한 층이 conv 전체보다 무겁습니다.
    - **GAP 방식**: 같은 `[512, 7, 7]`을 채널별로 평균내면 `[512]`가 됩니다. **이 평균 연산에는 학습 파라미터가 0개입니다.** 뒤에 붙는 분류 FC도 $512 \times 1000 \approx$ **51만 개**로 끝납니다.
    - **약 200배 차이**입니다. ResNet-34가 VGG-19보다 훨씬 깊은데도 파라미터는 더 적은 이유의 상당 부분이 여기 있습니다.
    - **왜 이렇게까지 줄여도 되는가**: flatten + FC는 "512번 채널이 **오른쪽 위 구석**에서 반응했다"까지 구분해 학습합니다. 하지만 분류에서는 고양이가 사진 어디에 있든 고양이입니다. 위치별 가중치는 **대부분 낭비이고 오히려 위치에 과적합할 여지**입니다. GAP은 그 자유도를 아예 제거해 버립니다 — 파라미터가 줄어드는 건 결과이고, 목적은 위치 불변성을 구조로 강제하는 쪽입니다.
- **부수 효과 — 입력 크기 자유**: `AdaptiveAvgPool2d((1,1))`은 H, W가 얼마든 `1×1`로 만들어 주므로, 학습 때와 다른 해상도의 이미지를 넣어도 FC의 입력 크기가 변하지 않습니다. flatten + FC 구조에서는 불가능한 일입니다.
- **구현 주의**: pooling 뒤 `torch.flatten(x, 1)`로 `[N, C, 1, 1]`을 `[N, C]`로 펴 준 다음 FC에 넣습니다. 이 flatten을 빠뜨리면 shape 에러가 납니다. → [쿡북](../Week%202/resnet_cookbook.md) [C6]
